# 인덱스 먼저

## 목적
같은 자료를 **매번 처음부터 다시 읽는 낭비**를 없앤다. 한 번 훑어 지도를 만들고, 다음부터는 지도만 본다.

## 입력
- 큰 파일(수백 쪽 PDF, 긴 회의록, 큰 표) 또는 파일이 많은 폴더

## 순서
1. 전체를 읽지 않는다. **겉만 훑는다.**
   - 문서 — 목차, 각 장 첫 문단, 표·그림 제목
   - 폴더 — 파일명, 크기, 수정일, 각 파일 첫 10줄
   - 표 — 시트명, 컬럼명, 행 수
2. `자료/_인덱스-<이름>.md` 를 만든다. 항목마다 한 줄:
   ```
   - <제목/파일명> · <무엇에 대한 것인지 한 줄> · <위치: 쪽수나 경로>
   ```
3. 맨 위에 **"무엇을 물으면 어디를 열면 되는지"** 3~5줄을 붙인다.
4. 다음부터 이 자료에 대한 질문이 오면 **인덱스를 먼저 읽고, 필요한 부분만** 연다.
5. 자료가 바뀌면 인덱스도 갱신한다. 인덱스가 낡으면 없느니만 못하다.

## 같이 쓰면 좋은 습관 (스킬이 아니라 습관이다)
- 일이 끝나면 `/clear` — 끝난 일의 맥락을 끌고 다니지 않는다
- 긴 결과는 화면에 뿌리지 말고 **파일로 빼고 경로만** 받는다
- "전부 읽고 알려줘" 대신 **"어디를 봐야 하는지부터 알려줘"**

## 결과
- `자료/_인덱스-*.md` 한 장
- 이후 같은 자료 작업에서 읽는 양이 줄어든다

## 하지 않을 것
- 인덱스를 만들겠다고 **전체를 먼저 다 읽지 않는다.** 그러면 목적이 없다.
- 인덱스에 내용을 옮겨 적지 않는다. **어디에 있는지**만 적는다.
- 작은 파일에 쓰지 않는다. 한 번에 읽히는 건 그냥 읽는다.
