# 교차검증

## 목적
**결론이 맞아도 근거 문장이 틀리면** 설명하는 자리에서 신뢰가 깎인다. 내가 쓴 것을 내가 검토하면 같은 착각을 두 번 한다. 그래서 **다른 모델에게** 시킨다.

## 언제 돌리나
- 고객·상사·외부에 나가는 문서
- 숫자·날짜·인용이 들어간 보고서
- "이건 확실하다"고 쓴 문장이 있을 때

내부 메모나 초안에는 쓰지 않는다. 매번 돌리면 안 돌리게 된다.

## 입력
- 검증할 파일 경로 또는 주장 목록
- 없으면 `결과물/` 의 최근 문서에서 **검증 가능한 주장만** 뽑아 목록으로 만든다

## 순서
1. 문서에서 **검증 가능한 문장만** 뽑는다. 숫자·날짜·인과관계·"~이다" 단정문. 의견과 제안은 뺀다.
2. 목록을 `결과물/검증-<주제>-YYYYMMDD.md` 에 먼저 적는다.
3. 코덱스가 있는지 확인한다.
   ```bash
   command -v codex
   ```
4. **있으면** — 적대적으로 태운다. 주장 목록을 그대로 넣는다.
   ```bash
   codex exec -s workspace-write --skip-git-repo-check "아래 주장을 하나씩 검증해라.
   맞으면 '확인', 틀리면 무엇이 어떻게 틀렸는지, 확인 불가면 '확인불가'로 답해라.
   동의하려 하지 말고 반례를 먼저 찾아라.

   <주장 목록>"
   ```
5. **없으면** — 건너뛰지 말고 대신 이렇게 한다.
   - 주장마다 **반대 근거를 먼저** 찾아본다
   - 숫자는 원 출처를 다시 열어 대조한다
   - 결과에 "코덱스 검증 안 함"을 명시한다
6. 결과를 세 칸으로 정리한다 — **확인 / 틀림 / 확인불가**
7. "틀림"이 하나라도 있으면 **원문을 고칠지 물어본다.**

## 결과
- `결과물/검증-*.md` — 주장별 확인/틀림/확인불가 + 근거
- 원문 수정 제안

## 하지 않을 것
- **결과를 요약하면서 부드럽게 만들지 않는다.** "대체로 맞다"는 없다. 문장 단위로 판정한다.
- 고객 개인정보가 든 문장을 그대로 코덱스에 넣지 않는다. 먼저 `hfk-privacy-check`.
- 의견·제안까지 검증 목록에 넣지 않는다. 사실만.
- 검증을 돌렸다는 이유로 "검증 완료"라고 쓰지 않는다. **확인불가 항목을 같이 남긴다.**
