# 스킬 만들기

## 목적
방금 한 일, 또는 매번 반복하는 일을 **다음부터는 한 줄로 시킬 수 있게** 파일로 남긴다.

## 입력
둘 중 아무거나. 없으면 물어본다.
- 네 줄 메모 — 무엇을 **열고** · 무엇을 **보고** · 무엇을 **만들어** · **누구에게** 주는지
- 방금 이 대화에서 실제로 한 작업 (그대로 절차로 옮긴다)

## 순서
1. 네 줄이 없으면 먼저 받는다. "이걸 신입에게 시킨다면 뭐라고 말할까" 한 문장이면 된다.
2. 이름을 정한다. **`hfk-` 없이, 영문 소문자와 하이픈**으로. (`결석-문자-초안` → `absence-sms-draft`)
3. `.claude/skills/<이름>/SKILL.md` 를 만든다. 아래 다섯 칸을 반드시 채운다.
   - **목적** 한 줄 / **입력** 어디서 뭘 받나 / **순서** 3~7단계 / **결과** 어디에 무엇이 남나 / **하지 않을 것**
4. `description` 에는 **멤버가 실제로 말할 법한 문장**을 3개 이상 적는다. 이게 있어야 나중에 자동으로 불려 나온다.
5. 만든 직후 **그 자리에서 한 번 돌려본다.** 안 돌면 스킬이 아니라 메모다.
6. `기록/worklog/` 에 한 줄 남긴다. (hfk-worklog 참고)

## 결과
- `.claude/skills/<이름>/SKILL.md` 한 장
- 그 스킬이 **실제 파일 한 건 이상에 돌아간 상태**

## 하지 않을 것
- 다섯 칸 중 **"하지 않을 것"을 비워두지 않는다.** 이 칸이 스킬을 안전하게 만든다.
- 절차를 코드로 먼저 짜지 않는다. **자연어로 적는 게 스킬이다.** 스크립트는 같은 절차를 세 번 돌린 뒤에 생각한다.
- 한 스킬에 일을 두세 개 넣지 않는다. 나뉘면 나눈다.
- `design` `slides` `brand` 처럼 **흔한 이름을 쓰지 않는다.** 엉뚱한 작업에서 튀어나온다.
